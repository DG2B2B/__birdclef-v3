# AgentSprintSpecs.md

```markdown
# BirdCLEF 2026 – Spécifications par Agent et par Sprint

Ce document détaille, pour chaque agent et chaque phase, les spécifications d’entrée/sortie, les dépendances, les tâches précises et les critères de succès. Il sert de “plan des plans” pour l’humain qui orchestre le développement.

## Règles communes
- Tous les agents génèrent du code Python 3.10, compatible PyTorch 2.4, `timm`, `torchaudio`, `librosa`, `onnx`, `onnxruntime`.
- Les modules sont sauvegardés dans le répertoire `src/` avec des noms explicites.
- Chaque phase produit un notebook Kaggle de test (ou un script `.py`) et des artefacts (modèles, fichiers ONNX, logs).
- Les poids des modèles sont sauvegardés en `.pth` pour les professeurs, en `.onnx` pour les élèves finaux.
- Les données d’entraînement sont supposées déjà segmentées et prétraitées par la phase 1 (dossier `data/train_segments`).
- **⚠️ 28 espèces zero-shot** (3 Amphibia + 25 Insect sonotypes 47158son01-25) sans aucun fichier train. Prédictions obligatoires => données Xeno-Canto requises.

---

## Phase 1 : Prétraitement Audio et Feature Engineering
**Agent : Gemini 3.1 Pro**  
**Dépendances :** Données brutes dans `data/train_audio`, métadonnées `train_metadata.csv`.  
**Livrables :**
- Script `src/preprocessing.py` avec :
  - `resample_and_segment(audio_path, sr=32000, duration=5)` → liste de tableaux numpy.
  - `log_mel_spectrogram(y, sr, n_mels=224, hop_length=320, win_length=800)` → array (224, temps). Tronquer / padder à 224 trames pour obtenir 224×224.
  - Normalisation : calcul de mean et std sur un sous‑ensemble aléatoire de 5000 segments ; sauvegarde dans `data/norm_stats.pkl`.
  - Filtre de silence : suppression des segments dont l’amplitude max est < -40 dB.
- Dataset PyTorch `src/dataset.py` :
  - Hérite de `torch.utils.data.Dataset`.
  - Lit un fichier CSV contenant les chemins et labels multi‑hot.
  - Applique les transformations : `torchaudio.transforms.SpecAugment` (time_mask_param=20, freq_mask_param=10), mixup additif (alpha=0.4).
  - Retourne (spectrogramme 3×224×224, label binaire 234).
- Notebook de test : charge le dataset et affiche un batch.

**Contrainte :** Le code doit être propre, type‑hinté, avec docstrings.

---

## Phase 2 : Modèles Professeurs CNN
**Agent : Gemini 3.1 Pro**  
**Dépendances :** Phase 1 terminée, dossier `data/train_segments` et `norm_stats.pkl`.  
**Livrables :**
- Script `src/models_cnn.py` contenant les classes :
  - `BirdClassifier(model_name, n_classes=234, pretrained=True)` avec GeM pooling (p=3) et tête linéaire.
  - Constructeurs pour `'efficientnet_b3'`, `'se_resnext50'`, `'nfnet_f0'`.
- Script `src/train_professors.py` :
  - Boucle d’entraînement 5‑fold, splits fournis par `iterative-stratification`.
  - Loss : `FocalLoss(alpha=0.25, gamma=2.0)` (implémentation personnalisée ou `torchvision.ops.sigmoid_focal_loss`).
  - Optimiseur : `AdamW(lr=1e-3, weight_decay=1e-4)`, scheduler `CosineAnnealingLR` avec warmup 5% (LinearLR).
  - Early stopping sur validation loss.
  - TTA (5 crops) en validation.
  - Sauvegarde des meilleurs poids par fold dans `models/teachers/{model_name}_fold{i}.pth`.
- Fichier `configs/train_teachers.yaml` : hyperparamètres, chemins.
- Notebook de test : entraîne 1 fold de chaque architecture, vérifie la non‑régression (score public simulé > 0.85).

**Suivi :** Gemini doit reporter les courbes de loss et macro‑AUC pour chaque fold.

---

## Phase 3 : Modèle Conformer
**Agent : Claude Sonnet 4.6**  
**Dépendances :** Dataset de la phase 1, mais avec une représentation séquentielle (segments plus longs, ex. 10 s → 100 trames de Mel).  
**Livrables :**
- Script `src/conformer.py` :
  - Implémentation d’un Conformer bloc (Macaron Net, self‑attention, convolution module).
  - Environ 6 blocs, dimension 256, 4 têtes, kernel convolution 31.
  - En entrée : (batch, T, 224) où T=100.
  - En sortie : pooling par attention multi‑tête sur la dimension temporelle, puis tête linéaire 234.
- Script `src/train_conformer.py` adapté à la longueur de séquence, même configuration d’optimisation (FocalLoss, AdamW, scheduler).
- Adaptation du dataset pour générer des séquences de 100 trames.
- Sauvegarde des poids dans `models/teachers/conformer_fold{i}.pth`.

**Spécificité :** Claude doit fournir une explication détaillée du mécanisme d’attention et du padding/masking.

---

## Phase 4 : Pseudo‑étiquetage Itératif
**Agent : Claude Sonnet 4.6**  
**Dépendances :** Modèles professeurs entraînés (phase 2 et 3), fichiers test soundscapes.  
**Livrables :**
- Script `src/pseudo_label.py` :
  - Pour chaque soundscape, extraire 120 segments de 5 s avec le prétraitement de la phase 1.
  - Inférer avec le meilleur fold de chaque architecture.
  - Moyenner les probabilités, appliquer seuil 0.9 → vecteur binaire.
  - Générer un nouveau CSV `data/pl_train.csv` combinant les données originales (50 %) et pseudo‑labelisées (50 %), avec le flag `is_pseudo`.
- Script `src/train_with_pl.py` : ré‑entraînement de tous les professeurs sur le dataset enrichi (FocalLoss, avec pondération ?).
- Itération : répéter 2 fois maximum si le score de validation s’améliore.
- Rapport textuel expliquant les itérations et l’évolution du score.

**Critère de succès :** Gain de +0.02 macro‑AUC sur le fold validation par rapport aux modèles sans pseudo‑labels.

---

## Phase 5 : Distillation Professeurs → Élèves
**Agent : Claude Sonnet 4.6**  
**Dépendances :** Modèles professeurs finaux, dataset enrichi (phase 4), architectures élèves (EfficientNet‑B0, EfficientVit‑b0, MnasNet‑100).  
**Livrables :**
- Script `src/distillation.py` :
  - Classe `DistillationLoss(alpha=0.7, T=2.0)` combinant BCEWithLogitsLoss et KLDivLoss.
  - Fonction `generate_teacher_logits(dataset)` : parcourt le dataset et calcule les logits moyens des professeurs (moyenne sur folds et sur architectures).
  - Boucle d’entraînement élève : charge les logits professeurs pré‑calculés (fichier `.pt`), applique la distillation loss.
  - Sauvegarde des poids dans `models/students/{name}_fold{i}.pth`.
- Documentation expliquant le choix de α et T.

---

## Phase 6 : Fusion et Calibration
**Agent : GPT Codex 5.4**  
**Dépendances :** Modèles élèves (phase 5), données de validation.  
**Livrables :**
- Script `src/fusion.py` :
  - Charge les élèves et calcule leurs probabilités sur la validation.
  - Optimise les poids `w_i` (Σ w_i = 1, w_i ≥ 0) via `scipy.optimize.minimize` ou Optuna pour maximiser le macro‑AUC.
  - Applique calibration Platt par espèce avec `sklearn.calibration.CalibratedClassifierCV`.
  - Sauvegarde `models/weights.json` et `models/calibrators.pkl`.
- Notebook de test évaluant l’ensemble final sur les données de validation.

**Exigence :** Code ultra‑robuste, testé unitairement.

---

## Phase 7 : Export ONNX et Optimisation CPU
**Agent : GPT Codex 5.4**  
**Dépendances :** Modèles élèves `.pth`, scripts des architectures.  
**Livrables :**
- Script `src/export_onnx.py` :
  - Convertit chaque élève en ONNX avec `torch.onnx.export`, `opset_version=17`, axes dynamiques pour la dimension batch.
  - Vérifie la sortie avec `onnxruntime`.
  - Quantification dynamique (opérationnelle avec `onnxruntime.transformers`, si bénéfique et sans perte de précision).
  - Enregistre dans `models/onnx/` : `effnet_b0.onnx`, `effvit_b0.onnx`, `mnasnet.onnx`.
- Benchmark : mesurer le temps d’inférence pour 1000 segments et s’assurer qu’il est inférieur à 15 ms par segment (CPU).

## Phase 8 : Notebook de Soumission Final
**Agent : GPT Codex 5.4**  
**Dépendances :** Modèles ONNX, poids de fusion, calibrateurs.  
**Livrable :** Notebook unique `submission_notebook.ipynb` conforme au `KaggleDeploy.md` déjà défini. Doit contenir :
  - Lecture des soundscapes, découpage, extraction log‑mel normalisée.
  - Inférence batch (batch_size=64) avec les trois modèles ONNX.
  - Fusion pondérée et calibration.
  - Génération du CSV final.
  - Affichage du temps d’exécution.

**Validation :** Le notebook doit être testé en mode hors‑ligne avec un petit dataset et terminer sans erreur. Doit utiliser `os.environ['KAGGLE_NO_INTERNET'] = '1'`.
