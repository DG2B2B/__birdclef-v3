```markdown
# BirdCLEF 2026 – Spécifications Globales

## Objectif
Atteindre la première place du leaderboard de la compétition Kaggle BirdCLEF 2026 en produisant un notebook d’inférence CPU performant (macro‑averaged ROC‑AUC maximal).

## Contexte
- **Compétition** : [BirdCLEF 2026](https://www.kaggle.com/competitions/birdclef-2026)
- **Dates** : fin le 3 juin 2026
- **Tâche** : classification multi‑label d’espèces d’oiseaux dans des enregistrements audio de paysages sonores (soundscapes).
- **Métrique** : macro-averaged ROC-AUC sur 234 espèces (235 colonnes dans le CSV = row_id + 234 espèces).
- **Contrainte majeure** : inférence CPU en moins de 90 minutes (notebook Kaggle sans Internet, 8 cœurs, ~16 Go RAM).

## Données
- **Train** : `train_audio/` (35 550 fichiers `.ogg`) couvrant **206 espèces** sur 234.
- **⚠️ 28 espèces zero-shot** : 3 Amphibia (1491113, 25073, 517063) + 25 Insect sonotypes (47158son01-25) -- aucun fichier train. Données Xeno-Canto indispensables.
- **Test** : `test_soundscapes/` (audio ~5 min, caché). row_id = `{soundscape}_{end_time_seconds}`.
- **Metadata** : `train.csv` (35 550 lignes), `taxonomy.csv` (234 espèces, 5 classes : Amphibia/Aves/Insecta/Mammalia/Reptilia), `sample_submission.csv` (235 colonnes).
- **Ressource externe** : `perch_meta` (modèle Perch ONNX).
- **Données additionnelles** : Xeno-Canto (forum, `.mp3` 32 kHz) -- critiques pour les 28 espèces zero-shot. + 10 658 train soundscapes (1 479 segments labellisés, 75 espèces).
## Architecture de la Solution
### Pipeline de haut niveau
1. **Prétraitement audio** : nettoyage manuel des artefacts (voix humaines, silences), resampling 32 kHz, découpage en segments de 5 s (entraînement) et 20 s (optionnel). Filtrage des segments silencieux (< -40 dB).
2. **Extraction de caractéristiques** : Log‑Mel (224 bandes, 25ms/10ms, normalisation mean/std) + PCEN (Per‑Channel Energy Normalization, recommandé pour le bruit de fond du Pantanal). Empilement 3 canaux pour compatibilité CNN.
3. **Modèles de niveau 1 (professeurs) avec SED Head** – Sound Event Detection (prédictions framewise) :
   - EfficientNet‑B3 (timm) — SED head: GeM frequency pooling + classification par trame
   - EfficientNet‑B0 (timm)
   - NFNet‑F0 (timm)
   - SE‑ResNeXt50 (timm)
   - Conformer léger (6 blocs, dim 256, 4 têtes) pour modélisation temporelle
   - Perch fine‑tuné via embeddings ONNX (optionnel)
   - Modèle dédié espèces rares / Amphibia-Insecta (entraîné sur données Xeno‑Canto additionnelles)
4. **Pseudo‑étiquetage itératif avec Power Transform** (technique 1er 2025) :
   - 3-4 itérations sur les soundscapes de test avec Power Transform pour nettoyer les labels.
   - MixUp à blending fixe 0.5 entre données labelisées et pseudo‑labelisées (ratio 1:1).
   - Stochastic Depth (`drop_path_rate=0.15`) pour régularisation Noisy Student.
5. **Modèles de niveau 2 (élèves)** – Distillation par knowledge distillation :
   - EfficientNet‑B0
   - EfficientVit‑b0 (timm)
   - MnasNet‑100 (timm)
   Les élèves apprennent à partir des logits agrégés des professeurs (et des labels réels).
6. **Fusion finale** :
   - Moyenne pondérée des probabilités des élèves (poids optimisés sur validation OOF).
   - Stacking possible avec méta‑modèle léger (régression logistique) sur prédictions OOF.
   - Calibration Platt / isotonique par espèce (optionnelle, à valider).
7. **Optimisation inférence** :
   - Export ONNX pour chaque modèle élève (opset 17).
   - OpenVINO comme alternative (×3 speedup CPU, utilisé par le 1er 2025).
   - Sliding window avec overlap + lissage temporel `[0.1, 0.2, 0.4, 0.2, 0.1]`.
   - Batch inference CPU (batch size 64), `gc.collect()` périodique.

## Validation
- **GroupKFold** par `site_id` / `location` / `recordist` (évite le leakage de bruit de fond entre train et validation). 5 folds, seed 42.
- Validation sur 100 % des données en fin d’entraînement (pas de hold‑out gaspillé).
- Test sur le soundscape `COL` pour vérification locale.

## Technologies
- **Langage** : Python 3.10
- **Framework** : PyTorch 2.4+, torchaudio, torchvision
- **Librairies** : timm, transformers, librosa, scikit‑learn, onnx, onnxruntime, iterative‑stratification, pandas, numpy
- **Environnement Kaggle** : Docker `nvidia/pytorch:24.02-py3` (GPU P100 ou T4x2 pour entraînement ; CPU pour inférence)

## Métriques et suivi
- Loss professeurs : Focal Loss (alpha=0.25, gamma=2.0). Loss élèves : 0.7×BCEWithLogitsLoss + 0.3×KLDivLoss(T=2).
- Optimiseur : AdamW (lr 1e‑3, weight decay 1e‑4), scheduler : CosineAnnealingLR avec warmup linéaire (5 % des steps).
- Early stopping : patience 10 epochs sur validation loss.
- Epoch max : 80 pour niveau 1, 40 pour niveau 2.
- Augmentations : SpecAugment + Background Mix (pluie/insectes/vent) + MixUp additif (blending fixe 0.5).
- TTA en validation : 5 crops aléatoires + flip horizontal ; Delta Shift TTA à l'inférence.

## Fichiers produits
- Notebook d’entraînement (GPU) : `train_pipeline.ipynb`
- Notebook de soumission (CPU) : `submission_notebook.ipynb`
- Modèles ONNX : `model_1.onnx`, `model_2.onnx`, …
- Scripts utilitaires : `utils/data_loader.py`, `utils/models.py`, `utils/distillation.py`, etc.
```

```markdown
# BirdCLEF 2026 – Plan de Développement (Sprints)

Ce document découpe le projet en sprints de 2 semaines, avec des objectifs, tâches et livrables.

## Sprint 0 : Mise en place de l’environnement et acquisition des données
- **Objectif** : Avoir toutes les données, les dépendances et une validation de base fonctionnelle.
- **Tâches** :
  1. Installer les librairies requises, configurer un notebook Kaggle avec accès Internet pour le téléchargement initial.
  2. Télécharger les données de la compétition + xeno‑canto supplémentaires (via le forum).
  3. Écrire le script de prétraitement audio :
     - Conversion en mono, resampling 32 kHz.
     - Segmentation en extraits de 5 secondes (pas de chevauchement pour les soundscapes, fenêtres glissantes pour l’entraînement).
     - Filtrage des silences (> -40 dB).
  4. Implémenter le loader PyTorch avec `transform` spec augment (SpecAugment) et mixup additif.
  5. Coder la métrique de validation macro‑AUC et un pipeline de validation croisée 5‑fold.
- **Livrable** : Notebook de test capable de charger les données, entraîner un CNN simple (EfficientNet‑B0) 2 epochs et calculer le score.

## Sprint 1 : Modèles de niveau 1 (professeurs) – Partie 1
- **Objectif** : Entraîner les premiers modèles CNN sur les données labelisées.
- **Tâches** :
  1. Architectures :
     - EfficientNet‑B3 (taille 224×224, 3 canaux, spectrogramme log‑mel empilé comme image RGB par répétition).
     - SE‑ResNeXt50.
     - NFNet‑F0.
  2. Entraînement 5‑fold, FocalLoss, optimiseur AdamW + scheduler, early stopping.
  3. TTA en validation : 5 crops aléatoires + flip horizontal.
  4. Sauvegarde des meilleurs poids par fold.
- **Livrable** : Un modèle de base (par architecture) avec score public > 0.88.

## Sprint 2 : Pseudo‑étiquetage et distillation itérative
- **Objectif** : Générer des pseudo‑labels robustes et les utiliser pour améliorer les modèles.
- **Tâches** :
  1. Prédiction sur les soundscapes de test avec le meilleur fold (chaque fichier de ~5 min → ~60 segments de 5 s).
  2. Agrégation des probabilités par espèce, seuillage à 0.9 → pseudo‑labels binaires.
  3. Création d’un nouvel ensemble d’entraînement : 50 % des échantillons originaux + 50 % des échantillons pseudo‑labelisés.
  4. Ré-entraînement de tous les modèles de niveau 1 sur cet ensemble (avec FocalLoss, en partant des poids pré-entraînés).
  5. Répéter une seconde itération si le score sur validation s’améliore.
- **Livrable** : Modèles professeurs finaux avec score > 0.91.

## Sprint 3 : Architecture temporelle et Conformer
- **Objectif** : Ajouter un modèle basé sur l’attention (Conformer) pour capturer la dynamique temporelle.
- **Tâches** :
  1. Implémenter un Conformer léger (6 blocs, 4 têtes, dim 256) prenant en entrée une séquence de 100 trames de spectrogramme (10 s → hop plus grand).
  2. Entraînement avec données labelisées + pseudo‑labels (mêmes splits).
  3. Intégration dans le pool de professeurs.
- **Livrable** : Modèle Conformer avec score > 0.90.

## Sprint 4 : Modèles élèves et distillation de connaissance
- **Objectif** : Obtenir des modèles légers pour l’inférence CPU, via distillation.
- **Tâches** :
  1. Sélection des architectures élèves : EfficientNet‑B0, EfficientVit‑b0, MnasNet‑100.
  2. Création d’un jeu de données enrichi (pseudo‑labels des professeurs) et calcul des logits professeurs moyens (somme pondérée des logits des profs avant softmax).
  3. Entraînement avec loss = 0.7 * BCEWithLogitsLoss(vrai labels) + 0.3 * KLDivLoss(logits profs, logits élève, T=2).
  4. Validation sur le fold correspondant.
- **Livrable** : Trois modèles élèves, chacun exportable en ONNX.

## Sprint 5 : Fusion, calibration et optimisation ONNX
- **Objectif** : Assembler l’ensemble final, calibrer et préparer le notebook de soumission.
- **Tâches** :
  1. Optimiser les poids de la combinaison (moyenne pondérée des probabilités) sur la validation via optimisation bayésienne (Optuna) ou simple validation croisée.
  2. Calibration Platt par espèce (Scikit‑learn `CalibratedClassifierCV` avec `method='sigmoid'` sur les scores de validation).
  3. Exporter chaque modèle élève en ONNX (dynamic batch size, `opset_version=17`).
  4. Écrire le code d’inférence CPU :
     - Chargement des fichiers ONNX.
     - Parcours des soundscapes de test, découpage en segments, inférence batch (batch size 64), moyenne pondérée, calibration.
     - Génération du fichier `submission.csv`.
  5. Vérifier le respect des contraintes de temps (doit tourner < 90 min CPU).
- **Livrable** : Notebook de soumission final prêt à être commité.
```

```python
def extract_logmel(y, sr):
    mel = librosa.feature.melspectrogram(y=y, sr=sr, n_mels=224, hop_length=320, win_length=800)
    logmel = librosa.power_to_db(mel, ref=np.max)
```

### 3.5 Inférence sur un soundscape

```python
def predict_soundscape(file_path):
    y, _ = librosa.load(file_path, sr=SAMPLE_RATE, mono=True)
    segments = []
    for start in range(0, len(y), SAMPLE_RATE * SEGMENT_LENGTH):
        seg = y[start:start + SAMPLE_RATE * SEGMENT_LENGTH]
        if len(seg) < SAMPLE_RATE * SEGMENT_LENGTH:
            break
        logmel = extract_logmel(seg, SAMPLE_RATE)  # (224, 224, 3)
        segments.append(logmel)
    
    segments = np.array(segments)  # (N, 224, 224, 3)
    preds = []
    for i in range(0, len(segments), BATCH_SIZE):
        batch = segments[i:i+BATCH_SIZE].transpose(0, 3, 1, 2)  # NCHW
        batch_pred = np.zeros((len(batch), 234))
        for w, model in zip(weights, models):
            out = model.run(None, {'input': batch})[0]  # (B, 234)
            batch_pred += w * out
        # Appliquer calibration si disponible
        preds.append(batch_pred)
    return np.concatenate(preds, axis=0)
```

# Architecture.md (document supplémentaire pratique)

```markdown
# Architecture Détaillée – Modèles et Flux de Données

## Représentation des données audio
- Tous les fichiers audio sont rééchantillonnés à **32 kHz**.
- Les extraits pour l’entraînement sont des segments de **5 secondes** sans chevauchement (pour l’inférence, même découpage).
- On extrait un spectrogramme Mel :
  - `n_mels = 224`
  - `hop_length = 320` (10 ms)
  - `win_length = 800` (25 ms)
  - Puissance en dB, normalisation par soustraction de la moyenne et division par l’écart-type (calculés sur l’ensemble d’entraînement).
- Le spectrogramme 2D (224, 224) est dupliqué en 3 canaux pour former une image RGB (taille d’entrée des CNN).

## Modèles professeurs (niveau 1)
| Modèle         | Backbone (timm)   | Entrée        | Paramètres |
|----------------|-------------------|---------------|------------|
| EffNet-B3      | `tf_efficientnet_b3.ns_jft_in1k` | 3×224×224 | 12.2M |
| SE-ResNeXt50   | `se_resnext50_32x4d`           | 3×224×224 | 27.5M |
| NFNet-F0       | `nfnet_f0`                     | 3×224×224 | 71.5M |
| Conformer      | Custom (6 blocs) | séquence (100, 224) | ~8M |

- Tous utilisent une tête de classification SED (framewise) de 234 sorties.
- Pooling : GeM pooling (p=3) avant la classification.

## Modèles élèves (niveau 2)
| Modèle         | Backbone            | Paramètres | Taille ONNX approx. |
|----------------|---------------------|------------|---------------------|
| EffNet-B0      | `tf_efficientnet_b0.ns_jft_in1k` | 5.3M | 20 Mo |
| EfficientVit-b0 | `efficientvit_b0`   | 3.5M | 14 Mo |
| MnasNet-100    | `mnasnet_100`       | 4.4M | 17 Mo |

- Même tête de classification et même pooling.

## Pipeline de distillation
1. Les professeurs (5 folds chacun) sont utilisés pour prédire les logits sur l’ensemble d’entraînement (données originales + pseudo‑labels).
2. Pour chaque échantillon, on moyenne les logits des 5 folds (pour chaque modèle professeur), puis on moyenne les logits entre les 4 architectures (pondération uniforme).
3. L’élève apprend avec :
   ```
   loss = α * BCEWithLogitsLoss(pred, label_bin) + (1-α) * KLDivLoss(log_softmax(pred/T), softmax(teacher_logits/T)) * T^2
   ```
   α = 0.7, T = 2.0.

## Stacking final
- Les probabilités finales sont Ψ = Σ w_i * σ( logits_i ), où i parcourt les élèves.
- Les poids w_i sont déterminés par une recherche sur grille (ou optimisation) pour maximiser le macro‑AUC sur la validation croisée.

## Calibration
- Optionnelle, appliquée espèce par espèce à l’aide d’une régression logistique (calibration Platt) sur les scores de validation.
- Si la calibration détériore le score public, l’omettre.
```
