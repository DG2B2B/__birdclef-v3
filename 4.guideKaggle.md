## Format de la Soumission

- **Fichier attendu** : `/kaggle/working/submission.csv`
- **Une ligne par fenêtre de 5 secondes** de chaque soundscape de test
- **259 colonnes** : `row_id` + une colonne par espèce (234 espèces)
- **Valeurs** : probabilités float entre 0 et 1 (pas de décisions binaires)
- **Métrique** : threshold-free → la qualité du ranking compte, pas le seuillage

### Exemple de structure `sample_submission.csv`

```

soundscape_00001_5,0.0,0.0,0.0,...
soundscape_00001_10,0.0,0.0,0.0,...

```

Le `row_id` est au format `{soundscape_filename}_{end_time_seconds}`.

## Architecture du Notebook de Soumission

Ton notebook doit être **inference-only**. L'entraînement se fait séparément.

### Pattern recommandé

```python
# ==================== IMPORTS ====================
import os, glob
import numpy as np
import pandas as pd
import librosa
import torch  # ou sklearn, etc.

# ==================== CONFIGURATION ====================
TEST_DIR = "/kaggle/input/birdclef-2026/test_soundscapes"
SAMPLE_SUB = "/kaggle/input/birdclef-2026/sample_submission.csv"
MODEL_PATH = "/kaggle/input/your-model-dataset/model.pth"  # ⭐ voir section modèle
OUTPUT_PATH = "/kaggle/working/submission.csv"
SEGMENT_DURATION = 5  # secondes
SR = 32000

# ==================== CHARGEMENT DU MODÈLE ====================
# Le modèle doit être uploadé comme Kaggle Dataset (voir section ci-dessous)
model = load_your_model(MODEL_PATH)
model.eval()

# ==================== INFERENCE SUR TEST ====================
sample_sub = pd.read_csv(SAMPLE_SUB)
species_cols = [c for c in sample_sub.columns if c != "row_id"]

results = []

for soundscape_path in glob.glob(f"{TEST_DIR}/*.ogg"):
    audio, sr = librosa.load(soundscape_path, sr=SR)
    soundscape_id = os.path.splitext(os.path.basename(soundscape_path))
    
    duration = len(audio) / sr
    
    for end_t in range(5, int(duration) + 1, 5):
        start_t = end_t - 5
        segment = audio[int(start_t * sr):int(end_t * sr)]
        
        # Preprocessing → feature extraction
        features = extract_features(segment, sr)
        
        # Inference
        with torch.no_grad():
            probs = model(features).cpu().numpy().squeeze()
        
        row_id = f"{soundscape_id}_{end_t}"
        results.append([row_id] + probs.tolist())

# ==================== SAUVEGARDE ====================
submission = pd.DataFrame(results, columns=["row_id"] + species_cols)

# S'assurer que tous les row_ids du sample_submission sont présents
submission = sample_sub[["row_id"]].merge(submission, on="row_id", how="left").fillna(0.0)

submission.to_csv(OUTPUT_PATH, index=False)
print(f"Submission saved: {submission.shape}")
```

## Comment Uploader Ton Modèle Entraîné

Puisqu'Internet est désactivé pendant le rerun, **ton modèle doit être disponible comme dataset Kaggle**.

### Étapes

1. **Entraîne ton modèle** localement ou sur un notebook Kaggle (avec GPU, 9h max)
2. **Sauvegarde les artefacts** : poids, scaler, label encoder, config, etc.
3. **Upload sur Kaggle** via :
    - Kaggle UI → `Datasets` → `New Dataset` → upload tes fichiers
    - OU Kaggle API : `kaggle datasets create -p ./mon_dossier_modele`
4. **Dans ton notebook de soumission** → `+ Add Data` → sélectionne ton dataset
5. Accès dans le notebook via `/kaggle/input/nom-de-ton-dataset/`

```bash

## Erreurs Courantes et Solutions

| Erreur Kaggle | Cause probable | Solution |
| :-- | :-- | :-- |
| `Notebook Timeout` | Inference trop lente sur CPU | Optimiser le modèle (quantization, ONNX, batch inference) |
| `Submission CSV Not Found` | `submission.csv` non écrit dans `/kaggle/working/` | Vérifier le chemin de sortie |
| `Submission Scoring / Format Error` | Mauvais colonnes, NaN, mauvais types | Utiliser la vérification de format ci-dessus |
| `Notebook Threw Exception` | Fichier manquant, path inexistant | Vérifier tous les `os.path.exists()` avant de lire |
| `Notebook Exceeded Allowed Compute` | RAM dépassée | Réduire batch size, libérer mémoire avec `del` + `gc.collect()` |

## Optimisation pour CPU (90 min)

```python
import onnxruntime as ort
import gc

# Utiliser ONNX pour 3-5x speedup sur CPU
sess = ort.InferenceSession("model.onnx", providers=["CPUExecutionProvider"])

# Libérer la mémoire régulièrement
for i, soundscape_path in enumerate(soundscape_files):
    # ... inference ...
    if i % 10 == 0:
        gc.collect()

# Batch inference pour amortir le overhead
batch_features = np.stack([feat1, feat2, ...])  # shape: (B, ...)
batch_probs = sess.run(None, {"input": batch_features})
```


### Techniques de speedup

- **ONNX export** depuis PyTorch/sklearn pour CPU optimisé
- **Batch processing** : traiter plusieurs segments à la fois
- **Mel spectrogram vectorisé** : pré-calculer en numpy/librosa sans boucles
- **Float16** si supporté par ton modèle
- **Limiter les workers** : Kaggle CPU a des ressources limitées

# Exemples de notebooks starters pour BirdCLEF 2026

Voici plusieurs approches de notebooks starters et baselines actuellement utilisés par la communauté pour la compétition BirdCLEF 2026. 

Puisque la compétition demande d'identifier 234 espèces dans des fenêtres de 5 secondes avec une contrainte de temps d'inférence CPU stricte (90 minutes max), les starters se divisent généralement en deux catégories : l'exploration des données (EDA) et les pipelines d'inférence avec des modèles pré-entraînés.[^2_1]

### 1. Les Starters basés sur des modèles pré-entraînés (Audio Spectrogram Transformers)
L'approche la plus solide et courante au début de BirdCLEF repose sur les modèles pré-entraînés sur des données audio massives.

* **Le Starter "Perch_v2"** : Des notebooks comme le `birdclef-2026-perch-v2-starter-readable-ver` utilisent le modèle Perch (développé par Google), qui est un modèle global d'embedding audio pré-entraîné sur des millions d'enregistrements d'oiseaux. L'avantage de ce starter est que le modèle Perch extrait directement des features audio très riches. Le notebook se contente généralement de :[^2_2]
  1. Charger les embeddings Perch via TensorFlow Hub ou un modèle Kaggle uploadé hors-ligne.
  2. Ajouter une simple tête de classification (Linear layer ou MLP) fine-tunée sur les 234 espèces du Pantanal.
  3. Gérer la boucle de fenêtrage de 5 secondes pour l'inférence.[^2_2]

* **Starters d'Intégration de modèles pré-entraînés** : D'autres baselines d'inférence, comme `birdclef-2026-pretrained-model-integration` ou `birdclef-26-inference-notebook`, montrent comment charger des modèles pré-entraînés comme BirdNET ou des architectures CNN (EfficientNet, ResNeSt) converties à partir de spectrogrammes Mel.[^2_3][^2_4]

### 2. Les Starters d'Exploration de Données (EDA) et Audio
Avant de lancer des modèles complexes, comprendre le *domain shift* (la différence acoustique entre les clips d'entraînement propres et les "soundscapes" de test très bruités) est crucial.[^2_1]

* **EDA + Audio Baselines** : Des notebooks comme `BirdCLEF 2026:Best Starter Notebook (EDA+Audio)` se concentrent sur le traitement du signal. Ils montrent comment :[^2_5]
  - Utiliser `librosa` pour charger les fichiers `.ogg`.
  - Convertir les signaux audio bruts en Mel Spectrogrammes ou MFCCs (Mel-frequency cepstral coefficients).
  - Visualiser la forme des appels d'oiseaux, le ratio de silence, et le bruit de fond (vent, pluie, insectes).[^2_1]
  - Mettre en place un pipeline d'inférence CPU basique avec un modèle linéaire ou un arbre de décision très léger pour vérifier que la mécanique de soumission fonctionne.[^2_6][^2_1]

### 3. Les Stratégies d'Inférence Optimisées (Fast Replay & CPU)
Puisque la soumission doit tourner sans GPU, un enjeu majeur des notebooks d'inférence est la vitesse.[^2_1]
* Les starters avancés mettent en place des optimisations comme l'export des modèles PyTorch vers **ONNX** ou **OpenVINO** pour accélérer drastiquement le calcul sur CPU.[^2_1]
* Ils montrent également comment vectoriser le traitement des fenêtres audio (batch processing) plutôt que de les traiter une par une dans une boucle `for`, et comment forcer le garbage collector (`gc.collect()`) pour éviter que le notebook ne plante par manque de RAM.[^2_1]

**Conseil pour ton pipeline :** Si ton modèle est prêt, je te conseille de chercher le notebook `[BIRDCLEF '26] Inference notebook` ou n'importe quel notebook nommé "Inference Only" dans l'onglet *Code* de la compétition. Tu pourras copier/coller leur boucle de fenêtrage (qui découpe le fichier de test caché en morceaux de 5 secondes) et y insérer l'appel à ton propre modèle, en t'assurant de bien uploader tes poids comme un *Kaggle Dataset* privé.[^2_3]

# Stratégies avancées du playbook Kaggle BirdCLEF 2026

Voici les stratégies avancées issues du playbook officiel et des discussions de haut niveau pour la compétition Kaggle BirdCLEF 2026. La clé de cette compétition n'est pas simplement d'entraîner un modèle massif, mais de gérer le "domain shift" (la différence entre les audios d'entraînement propres et les audios de test bruités) tout en respectant la contrainte d'inférence CPU de 90 minutes.[^3_1]

### 1. Gestion de la Validation (Cross-Validation)
C'est l'erreur numéro un des débutants : se fier au Leaderboard public (qui n'utilise qu'une fraction du dataset caché) ou utiliser un simple `train_test_split` aléatoire.[^3_1]
* **Stratégie de validation groupée (GroupKFold)** : Les données doivent être divisées (5 folds est le standard cette année) en utilisant des métadonnées contextuelles comme clés de regroupement (`site_id`, `location`, `recordist`, ou `date block`). Si tu as les mêmes sites d'enregistrement dans l'entraînement et la validation, ton modèle va "mémoriser" le bruit de fond de ce site au lieu d'apprendre le chant de l'oiseau.[^3_1]
* **Replay Protocol** : Puisque tester des idées sur 5 folds prend trop de temps, crée un "split fantôme" (1 seul fold, sous-ensemble de classes, seed fixe) pour tester très rapidement de nouvelles idées (loss, augmentations) avant de les lancer sur la CV complète.[^3_1]

### 2. Gestion du "Domain Shift" et Pseudo-Labeling
Les clips d'entraînement sont souvent centrés sur l'oiseau, tandis que les "soundscapes" de test (et de déploiement) contiennent de multiples espèces simultanées, de la pluie, du vent et des insectes.[^3_1]
* **Pseudo-Labeling sur les Soundscapes** : C'est la technique qui a gagné les éditions précédentes. Utilise ton meilleur modèle (même s'il est trop lent pour les 90 minutes requises) comme "Teacher" pour prédire des labels sur les `train_soundscapes` (ou d'autres données non labellisées).[^3_1]
* **Distillation vers un "Student" CPU-Friendly** : Utilise ces pseudo-labels pour entraîner un modèle plus petit (le "Student", par exemple un EfficientNetV2-B0 ) qui sera capable de tourner en moins de 90 minutes sur CPU tout en conservant les performances du modèle lourd.[^3_2][^3_1]

### 3. Feature Engineering et Augmentations
Le passage du signal audio brut au Spectrogramme Mel est l'approche dominante.[^3_3]
* **Modifications des spectrogrammes** : Outre le Log-Mel classique, tester le **PCEN** (Per-Channel Energy Normalization) est très recommandé pour cette compétition car il gère beaucoup mieux l'énergie de fond constante (comme le bruit du vent ou de l'eau dans le Pantanal) par rapport au Log-Mel classique.[^3_1]
* **Augmentations ciblées** : Les augmentations doivent simuler les conditions de terrain. Utilise le *Background Mix* (mixer l'audio avec des enregistrements de pluie/insectes), le *SpecAugment* (masquage de bandes de fréquences/temps sur le spectrogramme), et le *Time shift*. Évite les distorsions extrêmes (warping) qui modifient sémantiquement le chant.[^3_1]

### 4. Modèles de Contexte (Sequence Models)
Une fenêtre stricte de 5 secondes peut couper un chant en deux ou manquer de contexte.
* Les compétiteurs avancés extraient les caractéristiques (features) de fenêtres adjacentes et utilisent un système d'Attention ou de Pooling temporel pour donner au modèle une vue sur 10 ou 15 secondes, tout en gardant des prédictions à l'échelle de 5 secondes. Attention cependant : cela ralentit considérablement l'inférence.[^3_1]

### 5. Optimisation Extrême pour le CPU
Pour éviter l'erreur `Notebook Timeout` (limite de 90m) :
* **Export ONNX / OpenVINO** : Convertis tes modèles PyTorch en format ONNX (`.onnx`). L'utilisation du `CPUExecutionProvider` d'ONNX Runtime est indispensable et offre un gain de vitesse critique par rapport à l'inférence PyTorch native.[^3_4][^3_1]
* **Batch Processing** : Ne traite pas les fenêtres de 5 secondes une par une dans une boucle. Extrais les spectrogrammes de tout le fichier, mets-les dans un grand tenseur numpy, et fais l'inférence par lots (batches).[^3_1]

### 6. Ensembling / Stacking
* **Diversité avant tout** : Ne fais pas une moyenne de 3 EfficientNets. Mélange un modèle CNN basé sur des spectrogrammes Log-Mel avec un modèle basé sur PCEN, ou un modèle utilisant des embeddings pré-entraînés (comme *Perch* ou *BirdNET*).[^3_1]
* Si tu utilises un Meta-Modèle (Stacking), entraîne-le strictement sur les prédictions Out-Of-Fold (OOF) de tes modèles de base, sinon tu vas créer une fuite de données (leakage) massive.[^3_1]

## 🥇 1ère Place — Nikita Babych

**Score : Public 0.933 / Privé 0.935**[^4_1]

**Titre : "Multi-Iterative Noisy Student Is All You Need"**[^4_1]

### Technique Centrale : Self-Training Itératif
La solution repose sur un entraînement en 4 itérations de pseudo-labeling progressif avec une *Power Transform* pour nettoyer les labels bruités à chaque cycle  :[^4_1]

| Iteration | Power value | Public LB |
|---|---|---|
| Baseline supervisé | — | 0.872 |
| 1 | 1 | 0.909 |
| 2 | 1 / 0.65 | 0.918 |
| 3 | 1 / 0.55 | 0.927 |
| **4** | **1 / 0.6** | **0.930** |

### Détails Clés

- **Chunks de 20 secondes** (pas 5s) pour capturer les appels répétitifs des Amphibia/Insecta ; la durée optimale a été validée empiriquement vs 5, 10, 15, 30 secondes[^4_1]
- **Architecture SED** (Sound Event Detection) avec GEM frequency pooling + 3 Mel Spectrograms en input[^4_1]
- **Backbones** : `tf_efficientnet_b0/b3/b4.ns_jft_in1k`, `regnety_008/016`, `eca_nfnet_l0` — les modèles plus lourds sont ajoutés progressivement à chaque itération[^4_1]
- **MixUp à blending fixe 0.5** (pas de distribution Beta variable) entre données labellisées et pseudo-labels de soundscapes — ratio optimal = 1.0 (100% des batches mixés)[^4_1]
- **Stochastic Depth** (`drop_path_rate=0.15`) essentiel pour le Noisy Student, inutile en supervision pure[^4_1]
- **Modèle dédié Amphibia/Insecta** entraîné sur 700 espèces Xeno-Canto (+0.003 LB)[^4_1]
- **Inférence** : sliding window avec overlapping + lissage `[0.1, 0.2, 0.4, 0.2, 0.1]` + Delta Shift TTA + **OpenVINO** pour CPU[^4_1]

### Paramètres Mel Spectrogram

```

sample_rate: 32000, mel_bins: 224, fmin: 0, fmax: 16000,
n_fft: 4096, hop_size: 1252, top_db: 80.0
→ Image size: (3, 224, 512) pour 20 secondes

```
